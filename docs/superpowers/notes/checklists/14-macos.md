# Step 14 on macOS: manual checks

Numbering goes on from `../macos-test.md` (14b ended at 369). Results go to `../macos-test-results.md`.

### 14c, themes from GitHub

370. **Get a theme.** Settings ▸ Appearance (or the palette's Get Theme…): after the settings, Get Theme. Paste a public GitHub repository with `.toml` themes at its top or in `themes/` (search GitHub for the `gezik-theme` topic, or any repository with a Gezik theme) and press Return: the line at the bottom counts the download, then each theme is a row. Click a row's `Not installed` button and point at `Install`: every window previews the theme; moving away goes back. Choose `Install`: `~/Library/Application Support/gezik/themes/<name>.toml` appears with `# Installed from …` as its first line, and an `Installed` row with `Use Now`, `Check for Updates`, `Open Source Page`, `Delete Theme`. `Use Now` switches to it; `Check for Updates` lists the same theme as `Installed` (unchanged); `Open Source Page` opens the repository in Safari; `Delete Theme` moves the file to the Trash. Also paste a `…/blob/main/x.toml` address, and `http://github.com/a/b` (refused, red line).
371. **Proxy.** If a network with a proxy (System Settings ▸ Network ▸ Proxies) is at hand: the download of 370 goes through it. Otherwise write "no proxy to test".

### 14d, settings export and import

372. **A Windows zip on the Mac.** On Windows, Settings ▸ Sync and Backup ▸ Export Settings (Enter on the path) with a theme of your own, a pin under `{home}` and a template; copy the zip to the Mac. On the Mac, Import Settings: paste the zip's path, Return. The rows say what each kind of file does ("replaces", "new") and how many settings change; choose Import. The theme, the pin (it opens the Mac's home folder) and the template (New ▸) work; `~/Library/Application Support/gezik/backups/` has a `gezik-settings-<time>.zip`. Undo Import ▸ Undo: the settings, the theme and the template are back as before (the theme and template gone).
373. **The red row.** Add a `[[commands]]` entry (any `run`) to the Windows `settings.toml`, export again and preview the zip on the Mac: a red "These run programs on this computer" row names the command, the bottom line is red. Cancel: nothing changes. Restore Backup lists the backup of 372; choosing it shows what it would put back.

### 14e, portable mode

374. **Next to Gezik.app.** Quit Gezik. Copy `Gezik.app` into a new folder, say `~/Desktop/GezikPortable/`, and run `touch ~/Desktop/GezikPortable/gezik-portable` (next to the app, not inside it). Note the time of `ls -lT ~/Library/Application\ Support/gezik`. Open that `Gezik.app` from Finder: `~/Desktop/GezikPortable/gezik-data/` appears with `settings.toml`, `themes/example.toml` and `templates/`; Settings ▸ Sync and Backup's first row says "Portable: settings are kept in …/gezik-data" and its `Open Data Folder` opens that folder in a tab. Change the theme, pin a folder, quit: only `gezik-data` changed, the `ls -lT` of Application Support is the same. With the installed Gezik also running, both windows are separate (a folder opened from the Terminal with `open -a` goes to the installed one). In the portable Gezik, the System Integration page's questions (say, Add to PATH) begin with "Gezik is running in portable mode from …". `codesign --verify ~/Desktop/GezikPortable/Gezik.app` still passes.
375. **App Translocation.** Zip that folder (`Gezik.app` and `gezik-portable`), AirDrop or download it to the Mac so it gets the quarantine flag (`xattr -l` shows `com.apple.quarantine`), unzip it in Downloads and open `Gezik.app` there by double-click: the status bar says "Move Gezik.app out of Downloads (or open it once from Finder after moving) to use portable mode" and the settings are the usual ones. Move the folder elsewhere in Finder and open it again: portable mode as in 374, no note.

### 14f, sync folder

376. **iCloud Drive with Windows.** On Windows, Settings ▸ Sync and Backup ▸ Keep Settings in a Folder: type an iCloud Drive (or Dropbox) folder, say `%USERPROFILE%\iCloudDrive\Gezik`, Enter. The row then says "Settings are kept in …"; `location.toml` in `%APPDATA%\gezik` names it with `{home}`; the folder has `settings.toml`, `themes/`, `templates/` and `machines/<COMPUTER>`. On the Mac, the same in `~/Library/Mobile Documents/com~apple~CloudDocs/Gezik` (or `~/Dropbox/Gezik`): the row "This folder has Gezik settings already": `Use the Settings in This Folder`. The Windows theme and pins show on the Mac; `~/Library/Application Support/gezik/backups/` has a new zip. Change the theme on Windows: within the sync delay the Mac follows. Right-click a row ▸ `Only on This Computer` on the Mac: the row says "this computer", `settings.local.toml` has the key, Windows does not change. Turn the tray on in System Integration on the Mac: `settings.local.toml` gets `[system]`, the folder's `settings.toml` does not.
377. **A conflicting copy.** Take both computers offline (Wi-Fi off), change a different setting on each (and one the same, say the theme), go online. If the service made a conflicting copy (Dropbox: `settings (… conflicted copy …).toml`; iCloud may make `settings 2.toml` or none), the status bar names it and Sync and Backup lists "Conflicting copy: …" with `Review…`: a row per key that differs, choose `Other copy` for one, `Merge`. `settings.toml` has that key from the copy and everything else as before, comments too; the copy is in the Trash. If no copy appeared, write which service and that both changes were kept (or which was lost).
378. **Folder away and Optimize Storage.** With iCloud's "Optimize Mac Storage" on, quit Gezik, open it: it starts normally (the settings file downloads when read). Then quit, rename the sync folder in Finder (as if Dropbox were not running), open Gezik: the status bar says "Settings folder not available — using the last copy", the window's settings are read-only, a new pin works but the row says it is not saved. Rename the folder back: within a moment the note goes and the pin is in the folder's `settings.toml`. Stop Keeping Settings There: the folder's settings come back to `~/Library/Application Support/gezik`, `location.toml` is gone, the folder is unchanged.
