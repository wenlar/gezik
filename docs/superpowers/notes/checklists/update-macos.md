# Automatic updates on macOS: manual checks

Numbering goes on after `highlight-where-macos.md` (425). Results go to `../macos-test-results.md`. Spec: `../../specs/2026-10-14-guncelleme-design.md`.

**Setup for 426–431** (a local feed; the release build ignores it, so these use the `measure` profile): build twice from this branch, once as is and once with the workspace version bumped (`version = "0.1.0-rc.99"` in the root `Cargo.toml`, not committed):
`cargo build --profile measure -p gezik && scripts/macos/make-app.sh target/measure/gezik 0.1.0-rc.2 /tmp/old` and the same with the bumped version into `/tmp/new`. Then `cd /tmp/new && COPYFILE_DISABLE=1 tar --no-mac-metadata -czf /tmp/feed/gezik-0.1.0-rc.99-macos-universal.app.tar.gz Gezik.app`, `cd /tmp/feed && shasum -a 256 *.tar.gz > SHA256SUMS.txt`, and write `/tmp/feed/releases.json`: `[{"tag_name": "v0.1.0-rc.99", "draft": false, "prerelease": true, "html_url": "https://github.com/wenlar/gezik/releases", "assets": [{"name": "gezik-0.1.0-rc.99-macos-universal.app.tar.gz", "browser_download_url": "/tmp/feed/gezik-0.1.0-rc.99-macos-universal.app.tar.gz", "size": <its size>}, {"name": "SHA256SUMS.txt", "browser_download_url": "/tmp/feed/SHA256SUMS.txt", "size": <its size>}]}]`. Copy `/tmp/old/Gezik.app` to `~/Applications/` and start it with `GEZIK_CONFIG_DIR=/tmp/gezik-cfg GEZIK_UPDATE_FEED=/tmp/feed/releases.json ~/Applications/Gezik.app/Contents/MacOS/gezik`.

426. **Ready note.** About 10 s after the window opens the status bar shows "Gezik 0.1.0-rc.99 is ready — installs when you close it · Restart now · What's new". `/tmp/gezik-cfg/update/0.1.0-rc.99/` holds `x/Gezik.app` and `ready`. Close the note with ✕, quit and start again: no note (once per version), `state.toml` has `[update] checked` and `told`.
427. **Install on ⌘Q.** Quit with ⌘Q (not the window's close button: that path is checked in 428): `~/Applications/Gezik.app` is now the new one (`Contents/MacOS/gezik --version` says `gezik 0.1.0-rc.99`), `~/Applications/Gezik.app.old` is the old one. Start it (Finder double-click works too: the ad hoc signature came with the tarball): about 10 s later "Updated to 0.1.0-rc.99 · What's new", and `Gezik.app.old` and `update/0.1.0-rc.99/` are gone.
428. **Restart now.** Put the old app back (`rm -rf ~/Applications/Gezik.app && cp -R /tmp/old/Gezik.app ~/Applications/`), remove `/tmp/gezik-cfg/state.toml`'s `[update]` lines, start as in the setup. On the ready note click **Restart now**: the window closes, a new Gezik opens with the same tabs (no second Dock icon left behind), and it is the new version. With a copy running in the operations panel first, Restart now asks before quitting, as quitting from the tray does.
429. **Disk image and App Translocation.** Mount the rc.2 dmg (or any dmg with this branch's app) and start Gezik from `/Volumes/…` with the feed set: only "Gezik 0.1.0-rc.99 is out · Download", nothing under `update/`. Same for an app run from Downloads with the quarantine mark (`xattr -w com.apple.quarantine "0081;00000000;Safari;" Gezik.app`, then open it from Finder so it is translocated): only the "is out" note.
430. **A bad package is not installed.** Change one byte of the tarball after writing `SHA256SUMS.txt`: no ready note, nothing under `update/0.1.0-rc.99/` but `SHA256SUMS.txt`; the system log (Console, or the terminal Gezik was started from) says "does not match its SHA-256". Put the right sum back, but give the tarball an x86_64-only or broken `gezik` (say `echo > Gezik.app/Contents/MacOS/gezik` before taring): no ready note ("does not start here or is not 0.1.0-rc.99").
431. **Settings and the menu.** Settings ▸ General ends with "Check for updates automatically", "Channel" (Auto, Stable, Pre) and the Updates row (its outcome, "Gezik 0.1.0-rc.2. Last check: <date>", **Check Now**). Help ▸ Check for Updates and the palette's "Check for Updates" say "Gezik is up to date" without a feed newer than the running one, and show the ready note again with one. `[update] check = false`: nothing is asked at start (no `update/` folder), Check for Updates still works.
432. **The first real update.** Once rc.3 (the first release with the updater) is installed in `/Applications` and a newer release is published: within a day of starting Gezik (or at once with Check for Updates) the ready note shows, ⌘Q installs it, the next start is the new version and says "Updated to". The network request in Little Snitch / `nettop` goes only to `api.github.com` and then `github.com` / `objects.githubusercontent.com` for the files.
