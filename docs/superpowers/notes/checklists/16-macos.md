# Step 16 on macOS: manual checks

Numbering goes on from `l10n-overflow-macos.md` (it ends at 396). Results go to `../macos-test-results.md`.

### 16a, inside archives

397. **Into a zip and back.** Make `x.zip` with Finder (Compress) from a folder `docs` holding a few files. Double-click it in Gezik: the list shows `docs` (no extraction, nothing new next to the zip). Go into `docs`; the address bar reads `…/x.zip/docs`. ⌘↑ twice: back in the zip's folder with `x.zip` selected. Type `<the folder>/x.zip/docs` in the address bar (⌘L): the same place opens. Right-click `x.zip`: **Open as Folder** and **Open with System App** are there; the latter opens Archive Utility.
398. **Look inside without extracting.** In a zip with a JPEG and a PDF: select the picture and press Space (Gezik's own Quick Look comes up even when `[system] quick-look = "system"`), arrow to the PDF: both show; the preview pane (Alt+P) shows them too. ⌘C on the PDF, switch to another tab showing a folder, ⌘V: the PDF lands there (⌘Z removes it). Pasting into Finder gives nothing (only the path as text: a known limit). Drag a selection under 256 MB from the zip onto the Desktop in Finder: the files appear there.
399. **Passwords and archives in archives.** A 7z made with `7z a -mhe=on -pgizli s.7z <files>` (header encrypted): double-click asks for the password; a wrong one asks again, Cancel leaves you where you were; the right one opens it, and opening a file inside does not ask again. A zip holding `src.tar.gz`: double-click the `.tar.gz` inside: its contents show (the status bar counts the entries while a large one is read).
400. **Back after a restart.** With a tab inside `x.zip/docs`, quit Gezik (⌘Q) and start it: the tab is there again. Quit, move `x.zip` to the Trash in Finder, start Gezik: the tab shows the zip's folder and the status bar says it no longer exists.

### 16b, writing to archives

401. **Change a zip and undo.** Make `x.zip` with Finder (Compress) from a folder with a few files and open it in Gezik. Drag two files from Finder into the zip's list: they appear, and the zip next to it still opens in Archive Utility with the old and new files. Rename one inside the zip (F2), delete another (⌘⌫: the question says it can be undone), make a new folder (⇧⌘N; its name opens for editing). After each step ⌘Z undoes it (the zip is back as it was; the old one was in the Trash). Drag a file from the zip with ⌥ or ⇧ onto a Gezik folder: it moves out (gone from the zip). Open the final zip with Archive Utility: its contents match what Gezik showed. A `.rar` or `.iso` opened in Gezik: a drop shows the forbidden cursor and the status bar says this kind of archive can only be read.
402. **Update in Archive.** In a zip, double-click a `.txt` (it opens in TextEdit), change it and save (⌘S): Gezik asks "notes.txt changed"; **Update in Archive** puts it back (Archive Utility shows the new text), **Ignore** asks again at the next save. Change it once more without updating and go up out of the zip (⌘↑): Gezik asks whether to update, discard or keep a copy in Downloads; **Keep a Copy in Downloads** leaves `notes.txt` there.

### 16c, commands in the address bar

403. **Run, select, stop.** In a folder with a few files, ⌘L, type `>ls -la` and press Return: the panel under the list shows the listing (zsh, the folder shown), the exit code `0` in green and the time. Select two files, run `>echo "$GEZIK_FILES"`: their two paths, one per line. Run `>sleep 30`: the header counts the seconds; **Stop** ends it at once ("Stopped"), and `ps ax | grep sleep` in Terminal shows no `sleep 30` left. Run `>ls nothing-here`: the error line in the warning color, the exit code in red. Paste `>ls` into the address bar and click elsewhere (no Return): nothing runs.
404. **No terminal, history.** `>vim` ends at once (or says it needs a terminal) and Gezik keeps answering; `>cat` (it waits for input) ends at once. Type `>` and press ↓: the commands run before are listed, newest first; ↓ to one and Return writes it into the field without running it; Return again runs it. `> echo secret` (a space after `>`) runs but is not in the list afterwards. Inside a zip or in the Trash, `>ls` only says "Commands run in a folder on disk".
