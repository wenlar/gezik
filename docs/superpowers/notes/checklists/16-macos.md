# Step 16 on macOS: manual checks

Numbering goes on from `l10n-overflow-macos.md` (it ends at 396). Results go to `../macos-test-results.md`.

### 16a, inside archives

397. **Into a zip and back.** Make `x.zip` with Finder (Compress) from a folder `docs` holding a few files. Double-click it in Gezik: the list shows `docs` (no extraction, nothing new next to the zip). Go into `docs`; the address bar reads `…/x.zip/docs`. ⌘↑ twice: back in the zip's folder with `x.zip` selected. Type `<the folder>/x.zip/docs` in the address bar (⌘L): the same place opens. Right-click `x.zip`: **Open as Folder** and **Open with System App** are there; the latter opens Archive Utility.
398. **Look inside without extracting.** In a zip with a JPEG and a PDF: select the picture and press Space (Gezik's own Quick Look comes up even when `[system] quick-look = "system"`), arrow to the PDF: both show; the preview pane (Alt+P) shows them too. ⌘C on the PDF, switch to another tab showing a folder, ⌘V: the PDF lands there (⌘Z removes it). Pasting into Finder gives nothing (only the path as text: a known limit). Drag a selection under 256 MB from the zip onto the Desktop in Finder: the files appear there.
399. **Passwords and archives in archives.** A 7z made with `7z a -mhe=on -pgizli s.7z <files>` (header encrypted): double-click asks for the password; a wrong one asks again, Cancel leaves you where you were; the right one opens it, and opening a file inside does not ask again. A zip holding `src.tar.gz`: double-click the `.tar.gz` inside: its contents show (the status bar counts the entries while a large one is read).
400. **Back after a restart.** With a tab inside `x.zip/docs`, quit Gezik (⌘Q) and start it: the tab is there again. Quit, move `x.zip` to the Trash in Finder, start Gezik: the tab shows the zip's folder and the status bar says it no longer exists.

### 16b, writing to archives

401. **Change a zip and undo.** Make `x.zip` with Finder (Compress) from a folder with a few files and open it in Gezik. Drag two files from Finder into the zip's list: they appear, and the zip next to it still opens in Archive Utility with the old and new files. Rename one inside the zip (F2), delete another (⌘⌫: the question says it can be undone), make a new folder (⇧⌘N; its name opens for editing). After each step ⌘Z undoes it (the zip is back as it was; the old one was in the Trash). Drag a file from the zip with ⌥ or ⇧ onto a Gezik folder: it moves out (gone from the zip). Open the final zip with Archive Utility: its contents match what Gezik showed. A `.rar` or `.iso` opened in Gezik: a drop shows the forbidden cursor and the status bar says this kind of archive can only be read.
402. **Update in Archive.** In a zip, double-click a `.txt` (it opens in TextEdit), change it and save (⌘S): Gezik asks "notes.txt changed"; **Update in Archive** puts it back (Archive Utility shows the new text), **Ignore** asks again at the next save. Change it once more without updating and go up out of the zip (⌘↑): Gezik asks whether to update, discard or keep a copy in Downloads; **Keep a Copy in Downloads** leaves `notes.txt` there.

### 16c, commands in the address bar

403. **Run, select, stop.** In a folder with a few files, ⌘L, type `>ls -la` and press Return: the panel under the list shows the listing (zsh, the folder shown), the exit code `0` in green and the time. Select two files, run `>echo "$GEZIK_FILES"`: their two paths, one per line. Run `>sleep 30`: the header counts the seconds; **Stop** ends it at once ("Stopped"), and `ps ax | grep sleep` in Terminal shows no `sleep 30` left. Run `>ls nothing-here`: the error line in the warning color, the exit code in red. Paste `>ls` into the address bar and click elsewhere (no Return): nothing runs.
404. **No terminal, history.** `>vim` ends at once (or says it needs a terminal) and Gezik keeps answering; `>cat` (it waits for input) ends at once. Type `>` and press ↓: the commands run before are listed, newest first; ↓ to one and Return writes it into the field without running it; Return again runs it. `> echo secret` (a space after `>`) runs but is not in the list afterwards. Inside a zip or in the Trash, `>ls` only says "Commands run in a folder on disk".

### 16d, Git status

405. **No install window, Homebrew's git.** On a Mac without the Command Line Tools (`xcode-select -p` fails; `sudo xcode-select --switch` refuses a folder that is not a developer folder, and `DEVELOPER_DIR=/nonexistent` still makes `xcode-select -p` succeed, so neither stands in for it): open a folder with a `.git` (copy one from another Mac). No "install the command line developer tools" window opens; the status bar says "Install Git to see repository status" once (not again in the next repository folder). `brew install git`, quit and start Gezik: the same folder shows marks (an orange dot on a changed file, a grey `?` on a new one), the status bar `⎇ main · 2 changed`. A folder outside any repository: `ps ax | grep git` shows no git while you browse it.
406. **Changes show by themselves.** In a repository folder, in Terminal: `echo x >> README.md` (orange dot within about 1 s), `git add README.md` (green dot), `git commit -m t` (mark gone, `⎇ main ↑1` if it has an upstream), `git checkout -b other` (the status bar says `other`). Add `build/` to `.gitignore`: the `build` folder turns faint. Turn on the Git column (header right-click ▸ Show Git), click its header (conflicts and changes first), Group by ▸ Git, type `git:changed` in the filter (Ctrl+F): only changed rows. Inside a zip in the repository: no marks, no Git column.

### 16e, Git commands

407. **Push and pull with your own credentials.** In a clone of a GitHub repository whose HTTPS credentials are in the Keychain (`git config credential.helper` says `osxkeychain`): change a file, right-click it ▸ Git ▸ **Stage** (the dot turns green, no panel), status bar `⎇ main` ▸ **Commit…**, type a message (a faint line at the 72nd column), ⌘↩: the panel shows git's output, exit code 0. Status bar menu ▸ **Push**: the output streams, the status bar loses `↑1`. In a clone over SSH (key in ssh-agent: `ssh-add -l` lists it), status bar menu ▸ **Pull** and **Fetch** work without a password box. Remove the key from the agent (`ssh-add -D`) and Pull again: it fails at once (no hang), the panel says `Permission denied (publickey)` and offers **Open in Terminal**: Terminal opens in the repository and ⌘V pastes `git pull`. **Switch Branch…** lists the local branches (the current one marked); choosing one switches (status bar shows it).
408. **Discard, undo, compare.** Change a tracked file and make a new untracked one; select both ▸ Git ▸ **Discard Changes…**: the question says they go to the Trash first; after it the tracked file is as committed and the new one is gone (both are in the Trash). ⌘Z: both come back with your changes. Change the file again, Git ▸ **Compare with HEAD**: Gezik's compare shows `HEAD - <name>` beside it; with `[tools] diff = "opendiff"` FileMerge opens instead. A repository with a `pre-commit` hook that prints a line and exits 1: Commit shows that line in the panel and the commit does not happen (the message is still there at the next Commit…).

### 16g, phones

409. **Found without libmtp, then the box.** With no libmtp (`brew uninstall libmtp`, nothing in `~/Library/Application Support/Gezik/tools/libmtp-*`): plug in an Android phone (unlocked, USB mode "File transfer"): within 2 s a row with its name shows under the drives (a USB stick or an iPhone shows none). Click it: the status bar says "Cannot open …: Phones need libmtp" and the box "libmtp needed" comes up. While the download is not published it says to `brew install libmtp` (OK only); once `MANIFEST` has the release: Download, then the phone opens by itself; **Where does it come from?** opens the `libmtp-1.1.23-1` release page. Unplug: the row goes, a tab on the phone goes to This PC with "… was disconnected".
410. **Homebrew's first.** `brew install libmtp`, quit and start Gezik, click the phone: it opens without any box (`lsof -p $(pgrep gezik) | grep libmtp` shows `/opt/homebrew/lib/libmtp.9.dylib` or `/usr/local/lib/…`). `[devices] libmtp = "/nonexistent/libmtp.dylib"`: still Homebrew's (a path that does not load is passed over).
411. **Work on the phone.** Its storages show; `DCIM/Camera` lists with sizes and dates. Copy photos and a folder to the Desktop (⌘C/⌘V, a drag into a Gezik folder): whole, dates the phone's. Paste a file and a folder with subfolders onto the phone (the phone's Files app sees them), ⌘Z deletes them; new folder (⇧⌘N), rename (F2, ⌘Z renames back), delete (asked, "cannot be undone"). Cancel a large video copy half way: nothing left on the Desktop or the phone. Unplug during a copy: the job ends with an error within seconds, Gezik keeps answering.
412. **Image Capture holds the phone.** Open Image Capture with the phone selected, then click the phone in Gezik: "Another app is using the phone (Image Capture, Android File Transfer). Quit it and try again." Quit Image Capture (and, if it still fails, `killall ptpcamerad`), click again: it opens. Gezik on a phone whose locked screen shows nothing: "Unlock the phone and choose File transfer…"; `[devices] phones = false`: the row goes.
