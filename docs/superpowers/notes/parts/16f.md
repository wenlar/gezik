# 16f: phones over MTP on Windows — notes

Plan `../../plans/2026-10-14-gelismis-16f.md`, spec `../../specs/2026-10-13-gelismis-design.md` §10.1, §10.2, §10.5, §14 16f.

## What is in

- **Engine** (`gezik-ops`): `Resources::vfs_roots` (the queue key of a place with no file on disk: a phone's id); the engine adds `vfs:<key>` to a job's roots and drives, so two jobs on one phone wait for each other as two on one drive do. `Outcome::VfsCreated { at }` and `VfsRenamed { from, to }`; undo deletes what was made on the phone and renames back (last first), through a maker gezik-vfs registers (`set_vfs_undo`; gezik-ops cannot name `VfsEditTask`).
- **Core**: `vfs::split_device` reads `mtp://Pixel 8/DCIM` (either slash, `..` folded); `Tabs::leave_device` sends a phone's tabs to This PC.
- **Platform** (`gezik-platform/src/mtp/`): `Device`, `Object`, the `Session` trait (`storages`, `list`, `read_to`, `put`, `mkdir`, `delete`, `rename`, `can_rename`, `writable`, `connected`); `devices()` reads the WPD interface list and names with cfgmgr32 (no COM), leaves out devices with a drive letter (their interface comes through the WPD bus enumerator: `wpdbusenum`) and numbers a repeated name (`Pixel 8 (2)`); `open(id)` is the WPD session (`windows.rs`): `PortableDeviceFTM` (free-threaded, so any worker may call it; `CoIncrementMTAUsage` keeps the apartment while the session lives), read-write else read-only on access denied, `EnumObjects` + `GetValues` per row, `GetStream` to read, `CreateObjectWithPropertiesAndData` to write (reverted on a stop: nothing half made), `CreateObjectWithPropertiesOnly` for folders, `Delete` with recursion (else children first), `SetValues(ORIGINAL_FILE_NAME)` to rename, `GetPropertyAttributes` for whether a rename is allowed, storage access for whether anything is writable. `watch_phones` (in `removal.rs`'s window subclass): `RegisterDeviceNotificationW` for `GUID_DEVINTERFACE_WPD`, arrival and removal call back on the UI thread.
- **VFS** (`gezik-vfs/src/mtp.rs`): `MtpVfs` with an `IdCache` (inner path → object, filled as folders are listed, a folder asked of the device each time it is listed); a second object of one name shows as `name (2)`, every change goes by id. `stage` takes files out whole with the phone's date (a failed or cancelled file is removed); `apply` does the edits one by one: puts (folders merge, nested clashes take the job's answer), new folders, renames (only within a folder), deletes. Replacing: written as `name.gezik-tmp`, the old one deleted, the new one renamed; where the phone refuses renames the old one goes first. An error that means the phone is gone (or a stop) ends the job at once; others are failure rows. `Vfs` got `can_rename`, `apply` and `device` (defaults for archives); `same_root` compares phones by id; `queue_key`. `VfsEditTask` on a phone: one plan item, no trash questions, one question for names taken (Replace / Skip / Keep both / Cancel, then "The old file is deleted before the new one is written" where renaming is refused); a move between folders on the phone is a copy and a delete.
- **App**: `phones.rs` (the list, `[devices] phones`, the watch started 500 ms after start, a worker reads the list on each event; a phone gone takes its tabs to This PC with "Pixel 8 was disconnected"); sidebar rows under the drives with a phone glyph, right-click Open / Open in new tab; `mtp://` typed or in a tab set or pin goes to the phone of that name; a phone not plugged in sends the tab to This PC with "Pixel 8 is not connected"; an empty phone top says "Unlock the phone and choose File transfer in its USB notification"; Delete asks "Delete … from the phone? This cannot be undone."; a read-only device says "This device can only be read"; search says "Phones are not searched".
- **Settings**: `[devices] phones = true` (template, schema, `docs/configuration.md`). `libmtp` comes with 16g.

## Deviations

1. **Phones are not `gezik_platform::Drive` rows** (spec §10.5 `device: Option<DeviceId>`): a list of their own in `phones.rs` and a sidebar section of their own under the drives; This PC's list does not show them (its rows are paths). Their rows are no drop targets.
2. **The drive-letter rule is the interface path** (`wpdbusenum`), not `WPD_DEVICE_TYPE` + functional category: it needs no COM and is a pure, tested rule.
3. **No thumbnails** (spec §10.1, optional in the user's decision): the grid shows file icons on a phone.
4. **One COM path for every thread** (`PortableDeviceFTM`), no dedicated MTA thread.
5. **"Update in Archive"** also works for a file opened from a phone (the same question and words; replaced without asking).
6. **The device event is registered on the first window only.**

## Known limits

- A folder is read with one property request per object (no bulk read): large camera folders list slowly.
- Dates are read as UTC (WPD gives the device's local time): off by the time zone (`shortcut:` in `windows.rs`).
- A name holding `/` or `\`, or `.`/`..`, is not shown.
- A file replaced on the phone has no undo; a delete on the phone has none either (asked first).
- If the first window closes while others stay, phones plugged in afterwards show at the next start.
- The 3 s drive poll is unchanged (spec §17).

## Checks for the maintainer (Windows, with a phone)

No phone was attached while this was written: the WPD code was compiled, and its read path (discovery, open, storages, listing, dates) was tried read-only against a USB stick WPD lists (`lists_portable_devices_read_only`, ignored, run by hand); discovery left the stick out and returned empty. The operations were tested against a fake device (`crates/gezik-vfs/tests/mtp.rs`). On a real phone (unlocked, USB mode "File transfer"):

1. Plug the phone in: within 2 s a row with its name shows under the drives (no row for a USB stick). Unplug: the row goes; a tab on the phone goes to This PC with "… was disconnected".
2. Open it: the storages show; `DCIM/Camera` lists with sizes and dates. Locked or in "Charging only": the note about File transfer; unlock, F5.
3. Type `mtp://<name>/Internal shared storage/DCIM` in the address bar; restart Gezik with a tab on the phone (comes back), and with the phone unplugged ("… is not connected", This PC).
4. Preview a photo (the preview pane, Space/Quick Look), open one with its app.
5. Copy several photos and a folder from DCIM to the desktop (Ctrl+C/Ctrl+V, Copy To…, a drag into a Gezik folder): contents whole, dates the phone's. Cancel a large video half way: nothing left on the desktop.
6. Paste a file and a folder with subfolders onto the phone; the phone's Files app sees them. Ctrl+Z deletes them on the phone.
7. Paste a file of a name already there: Replace / Skip / Keep both each do what they say; no `.gezik-tmp` left.
8. New folder (Ctrl+Shift+N), rename it (F2), Ctrl+Z renames back; delete a file (asked, "cannot be undone").
9. Two copies onto the phone at once: the second waits for the first.
10. Unplug the cable during a copy each way: the job ends with an error within seconds, Gezik does not hang, no half file on the desktop.
11. An iPhone: its photos show read only (Delete and paste say "This device can only be read").
12. `[devices] phones = false`: the row goes and does not come back on plugging in.
