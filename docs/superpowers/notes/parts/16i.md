# 16i: hard link — notlar

Spec: `../../specs/2026-10-15-tamamlayicilar-design.md` §3. Dal: `feat/hardlink-16i`.

## Ne yapıldı

- `LinkKind::Hard` (`gezik-core/src/templates.rs`); ad sembolik bağlantınınki gibi `Link to a.txt`, alınmışsa `Link to a (2).txt`.
- `gezik-platform/src/link.rs`: `create` için `LinkKind::Hard => std::fs::hard_link` (Windows'ta yönetici gerekmez).
- `LinkTask::plan` (`gezik-ops/src/tasks/link.rs`): hard link işinde, hiçbir şey yapılmadan önce tek denetim, tek mesaj: bir klasör varsa "Hard links work only on files", bağlantının klasörü kaynakla aynı sürücüde değilse "Hard links must stay on the same drive" (taşı/kopyala kararındaki `same_drive`, yani `drive_facts().id`). Geri alma bugünkü bağlantı geri alması (`Outcome::Created` → bağlantı çöpe; özgün dosya kalır).
- Bağlam menüsü: Windows'ta Create link ▸ **Hard link** (symlink'in ardından, `LINK_HARDLINK` = 1460); macOS/Linux'ta "Create link"in ardından **Create hard link**. Klasörde de gösterilir; görev nedeniyle reddeder (spec'teki mesaj).
- Bilgi penceresi (macOS/Linux): tek dosyada `nlink > 1` ise General'ın sonunda "Links: N". Klasörde yok (klasörün nlink'i alt klasör sayısıdır).
- Çeviriler: tr elle; de/es/fr/zh-Hans `fuzzy`; `gezik-lang check`: eksik yok. `docs/features.md` Create link satırı.

## Sapmalar

1. Menü adı "Hard link" (spec "Hard Link"): menüdeki "Symbolic link" gibi cümle düzeni. macOS/Linux'ta tek "Create link" öğesi olduğu için ikinci öğe "Create hard link".
2. Ön denetim UI iş parçacığında değil, görevin `plan`'ında (işçi iş parçacığı; sürücü kimliği okumak ağda yavaş olabilir). Yine de hiçbir bağlantı yapılmadan, tek hata satırı olarak.
3. ID 1460: 1404–1409 dolu, 1410–1459 şablonlar.

## Bilinen sınırlar

- "Başka sürücü" durumu bugünkü menüden oluşamaz (bağlantı kaynağın yanına yapılır); denetim `LinkTask::into` ile ileride hard link bırakma eklenirse diye. Başsız testi yok (iki sürücü gerekir).
- FAT/exFAT gibi hard link desteklemeyen sürücülerde sistemin hatası gösterilir (ön denetim yok).
- Sembolik bağlantıya hard link: `source.is_dir()` hedefi izler; klasöre giden sembolik bağlantı reddedilir, dosyaya giden ise sistemin davranışına kalır (Linux bağlantının kendisini, macOS hedefi bağlar).
- Windows Bilgi penceresinde bağlantı sayısı yok (spec §1).

## Testler

- `gezik-ops` `link`: hard link yapılır, içerik aynı, geri alma bağlantıyı çöpe atar ve özgün kalır; dosya + klasör seçiminde tek hata ve hiçbir şey yapılmaz.
- `gezik` `context_menu`: menü öğeleri ve `link_kind`; `info`: "Links: 3" satırı.

## Ekran testi (Windows)

- Bir dosyaya sağ tık ▸ Create link ▸ Hard link: `Link to a.txt` gelir, seçili. Birini düzenle, diğeri de değişir (`fsutil hardlink list a.txt` iki ad).
- Ctrl+Z: bağlantı Geri Dönüşüm Kutusu'na; `a.txt` yerinde. Ctrl+Y geri getirir.
- Dosya + klasör seçip Hard link: tek mesaj "Hard links work only on files", hiçbir şey yapılmaz.
- Tek klasöre sağ tık ▸ Hard link: aynı mesaj.

## Ekran testi (Windows, 2026-10-15, birleşik dal #170)

- a.txt ▸ Create link ▸ Hard link: `Link to a.txt` oluştu, `fsutil hardlink list` iki adı gösterdi. Ctrl+Z bağlantıyı çöpe attı, a.txt içeriğiyle kaldı.
- Klasör ▸ Hard link: hiçbir şey oluşmadı, ayrıntı "A: Hard links work only on files".
- **Küçük:** bu kalıcı ret için ayrıntı penceresinde yine Retry düğmesi var.
