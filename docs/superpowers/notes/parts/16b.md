# 16b: writing to archives — notes

Plan `../../plans/2026-10-14-gelismis-16b.md`, spec `../../specs/2026-10-13-gelismis-design.md` §6, §14 16b.

## What is in

- **Edits** (`gezik-core/src/vfs.rs`): `Edit::{Put, MakeDir, Delete, Rename}` and `Caps` (`WRITE`, `RENAME`, `MKDIR`, `DELETE`).
- **One checked rewrite** (`gezik-batch/src/tasks/add.rs`, `AddToArchiveTask` made general: `AddToArchiveTask::edit`, `rewrite`, `replace`): deletes and renames act on the archive's names (a folder with what it holds; a folder only its entries made stays when its last entry leaves), then new folders, then puts (the clash question as before). zip: the entries kept are copied raw (renamed ones with `raw_copy_file_rename`); 7z and tar (plain, gz, bz2, xz): unpacked into a staging folder and packed again with each entry's mode, date and owner. Names are checked (no empty, `.`, `..`, leading `/`, `\`, NUL; no folder into itself; no rename onto another entry).
- **Steps** (spec §6.2): (1) room next to the archive for the archive plus what is put in, else nothing is written; (2) written to the engine's temporary name next to it; (3) read back: the list must be the expected tree (names, folders, sizes), and new files (zip) or every file (7z, tar: all were packed again) are taken out and compared byte for byte with their sources; (4) the old archive steps aside (noted for recovery), the new one takes its name, the old one goes to the trash. A failure or cancel in 1–3 removes only the temporary file; a failure in 4 puts the old one back. Undo: the old archive from the trash. On a drive without a trash Gezik asks first ("The old archive cannot be kept for undo").
- **Passwords**: a zip's new entries take its password (AES-256), a 7z keeps its password and hidden names; the password the tab was given is used, else asked.
- **`gezik-vfs`**: `Vfs::caps`, `Vfs::archive` (the file and the password kept); an archive is writable when Gezik reads it itself, has a writer for it and, inside another archive, that one is writable. An inner archive counts as changed when its outer one changed (it is read again). `VfsEditTask`: edits in a place; nested archives are written in a private folder and put back into the archive they are in (`[Delete, Put]`), level by level, one undo (the outer file's old self); entries of another archive are taken out into a private folder first; a move in trashes only the files that went in whole; a move between archives deletes in the source only what went in; "Update in Archive" replaces without a question. `move_out`: copy out, then delete inside only what left the staging folder (a skipped conflict stays in the archive). The queue key stays the archive's file on disk (16a's decision).
- **Staging folders** (`RunCx::staging_dir`) are made 0700 on Unix: a repack unpacks (decrypted) contents there.
- **App**: inside an archive Gezik writes, Ctrl+V (files, or entries copied or cut in an archive), drops from Gezik or other programs (Shift moves; entries of the same archive move by default; never into itself), Delete / Shift+Delete (asked: "Delete … from the archive? You can undo this."), F2 (one entry, in a folder), Ctrl+Shift+N (a free "New folder", renamed once it shows), Ctrl+X, Move To…; out of it Cut + paste, Move To… and Shift-drags move. Row menu: Cut, Move To… (3233), Rename, Delete; empty space: Paste, New folder. In an archive Gezik only reads, these say "This kind of archive can only be read" (drops show the forbidden cursor). After a job the tab reads the archive again and selects what was made.
- **Update in Archive** (`vfs_mounts.rs`): a file opened with its app from a writable archive is watched (`FolderWatch`, no polling); a save (quiet for 400 ms) asks "notes.txt changed": Update in Archive / Ignore. When no tab shows the archive any more and a change was not put back: Update in Archive / Discard / Keep a Copy in Downloads (closing the question keeps a copy). At quit such a change is copied to Downloads before the temporary area goes.

## Deviations

1. **"Update in Archive" is a question in the window**, not a strip above the tab: no new Slint widget (size), and the same buttons.
2. **tar.zst stays read-only**: Gezik has only a zstd decoder (`ruzstd`); an encoder is C code or a new crate. With rar, iso, cab, cpio, ar/deb, single `.gz`/`.xz` files, archives in parts and 7-Zip's formats.
3. **Read-back is stronger than the spec for 7z and tar**: every file is compared, since all were packed again (zip: only new entries, as the spec says).
4. **The space check** counts the archive and what is put in, not the unpacked copy a 7z or tar repack makes.
5. **No `Vfs::apply` on the trait**: `VfsEditTask` writes archives through `gezik_batch::tasks::{rewrite, replace}`; phones (16f) can add it. `Caps` has no `RANDOM_READ`/`THUMBS`/`TRASH` yet (16f, with thumbnails).
6. **A right-button drag into an archive** acts as a left one (no Copy/Move menu). Drops on tabs or crumbs that show an archive place are not taken.
7. **Rename** works on one entry in an archive folder: not in search results inside an archive, no batch rename inside archives.
8. **Not done from 16a's follow-up list**: the lock badge on encrypted entries, grid thumbnails for zip, Extract to Preview.
9. **No new action** (as the spec says); Move To… inside an archive is the existing `move-to`.

## Known limits

- A file opened from an archive and left unchanged is let go with the archive when no tab shows it (its temporary copy goes, as in 16a); a later save in its app then has nowhere to go back to.
- Every change to a large solid 7z or tar.gz packs it all again and leaves the old one in the trash.
- A password asked during a nested write names the inner archive's temporary file.
