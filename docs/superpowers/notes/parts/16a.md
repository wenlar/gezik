# 16a: the VFS core and browsing archives — notes

Plan `../../plans/2026-10-13-gelismis-16a.md`, spec `../../specs/2026-10-13-gelismis-design.md` §4, §5, §14 16a.

## What is in

- **Types** (`gezik-core/src/vfs.rs`): `VfsPath { root, inner }`, `VfsRoot::{Archive(Container), Device}`, `Container::{Disk, Inside}`; the address text (`C:\a\b.zip\docs`, `mtp://Pixel 8/…`), `levels` for the session, `split_archive` (a typed path at its first archive file) and `split_inner` (the same inside an archive). `Location::Vfs`: up from an archive's top is its folder (from an inner archive's top, where it is in the outer one), `folder()` is `None` (terminal, commands, folder search stay off), `on_disk()` the archive file (a drive's eject lets go of it), crumbs one part per level, `nearest_existing` falls back to the archive's folder.
- **Readers** (`gezik-batch/src/archive`): `ExtractCx::wants(entry)` asked before an entry is written. `extract_some` (a default method of `ArchiveSource`) writes only the chosen names and what is under them, every format; `list_all` lists a stream (tar family, single `.gz`…, cpio, deb) by one pass writing nothing. The archive `Entry` has `modified` now.
- **`gezik-vfs`** (new crate): `Vfs` trait (`list`, `is_file`, `is_dir`, `packed`, `stage`, `staged`, `unchanged`); `ArchiveVfs` (index read once, Gezik's readers else 7-Zip: `7z l -slt -ba` and `7z x -i@list`, the password kept while open); the registry (`mount`/`mounted`, weak: the last holder lets go; a changed archive file is read again; an inner archive is taken out into the outer one's folder, at most 8 deep); the temporary area (`<temp>/gezik-vfs-<pid>/<n>`, dead processes' areas cleared on first use, a root's folder removed with it, the area at quit); `tasks::copy_out` (take out into a staging folder in the target, then `PlaceTask`: conflicts and one undo).
- **Index** (`archive/index.rs`): one name text, nodes laid out breadth first so a folder's children are side by side in name order (halving search), folders made from names, folder sizes summed, `..`/root/drive names left out, the later of two entries with one name kept. 100,000 entries: under 8 MB (test).
- **App**: `LoadResult::{Vfs, Redirect, Declined, SevenZipNeeded}`. A `Location::Path` that cannot be listed and leads through an archive file redirects inside (typed paths, tab sets, sessions, pins: one place); `list_vfs` mounts, lists, and redirects into an inner archive. `Listing::Vfs(Rc<VfsDir>, entries)`: `path_at` is `None` (what wants a real file is off), `item_at`/`vfs_item` give the `VfsPath`; sort, filter (name only), grouping, view memory (by address), type-ahead work as in a folder. `vfs_mounts.rs` holds the places tabs show (swept after every chrome update) and asks for passwords from worker threads (`UiCx`: a dialog in the window in front, the thread waits; a load overtaken stops waiting).
- **Opening**: `[archives] double-click = "browse"` (new default) and Enter go into an archive; a folder or an archive inside goes in, a file is taken out and opened with its app. Row menu: **Open as Folder**, **Open with System App** (ids 3200, 3201). Inside an archive Gezik's own menu: Open, Open in new tab, Copy, Copy To…, Copy Path (3230–3232); empty space: Undo, Redo, Refresh, Copy Path.
- **Copying out**: Ctrl+C keeps the entries in Gezik (the system clipboard gets their addresses as text); a paste into a folder, Copy To…, or a drop on a folder in Gezik runs `copy_out`. A drag to another program takes the selection out first (≤ 256 MB, started when the drag starts).
- **Preview and Quick Look**: a file up to `[archives] preview-limit` (64 MB) is taken out by the preview's thread, then shown as any file; a folder shows its count from the index. On macOS Space opens Gezik's own Quick Look inside archives.
- **Search inside an archive** (`Scope::Vfs`): the search bar opened in an archive searches its index (name, size, date, type) on a thread; the results are a `ResultSet` that knows the place (`ResultSet::inside`: `path_at` none, `item_at` the `VfsPath`), so opening, the preview, copying and dragging work on them as on rows. Content, tag and duplicate searches say they do not look inside archives. A saved search whose folder text leads into an archive is redirected there.
- **Packed column** (`ColumnKey::Packed`, header menu only inside an archive, not sortable). `browse-archive` action (`Action::ALL` 133), macOS File menu item. Watch: the archive's folder is watched; a change re-reads the index only if the archive changed; a deleted archive sends the tab to its folder. Session: `{ archive, inner = [...] }`, `{ device, device-name, inner }`; an older Gezik skips them.

- **After the code review (PR #139):**
  - A file is taken out into a fresh private folder and moved into its place only once whole (`stage_here`), one thread per file (others wait): a staged file is never half written, whatever stopped 7-Zip or a reader. A drag out gets a fresh folder of its own and is ready only when every item came out with no entry failed or skipped (`stage_into`).
  - The temporary area and every folder in it are made by Gezik itself, mode 0700 on Unix; an existing folder of that name is never used (another name is taken). 7-Zip's list of names lives in a private folder of its own, removed however the run ends; 7-Zip's warning exit (1) counts, what was asked for is checked to be there.
  - At most 1,000,000 entries (`MAX_LISTED`): a larger archive is refused, a stream stops being read there; the index drops each whole name as it splits it.
  - Mark of the Web (Windows): files handed to another program (opened with their app, dragged out, copied out) get the archive's own `Zone.Identifier`, as Explorer does; an archive without one gives none. The preview inside Gezik marks nothing. macOS quarantine is not copied (a follow-up).
  - Roots compare ignoring case on Windows (`same_root`); a copy inside an archive is pasted where the clipboard has no change number (Linux without one) only while it holds no other program's files.

## Deviations (also in the plan)

1. **A search inside an archive's results** skip Show in folder and Copy with folders (they need disk paths); a session keeps such a search tab as its search with the archive's address as the folder, and the load finds its way back in.
2. **`Resources::vfs_roots` comes with 16f**: an archive's key is its file on disk, already in `paths`, so jobs on one archive queue by its drive as the spec wants. Phones need the key.
3. **`Caps`, `Edit`/`apply` and `thumbnail` come with 16b/16f**, where something writes or a phone gives thumbnails. Grid thumbnails inside archives (`RANDOM_READ`, ≤ 8 MB) are not in 16a: rows show their kind's icon.
4. **No "Extract to Preview" button**: over `preview-limit` the preview shows the facts; opening the file takes it out.
5. **No lock badge** on encrypted entries yet (the Packed column and the password question are in).
6. **Progress while a stream archive is read** is the status bar's entry count ("Reading x.tar.gz: 12,345 items"); going elsewhere stops it (no Cancel button). A password question cancelled leaves the tab where it was.
7. **A drag to another program has no progress ring**: the items are taken out as soon as the drag starts; if they are not ready when the pointer leaves the window, the drag stays in Gezik and the status bar says so (over 256 MB: "Use Copy To… for large selections").
8. **Cut, Move To… and moving drags out of an archive are refused** with a note (a move needs 16b's delete inside).
9. **`docs/configuration.md`** lists no per-feature keys; `[archives]` is documented with the feature in `docs/features.md`, as before.
10. **`scripts/perf/archive.ps1` is not written** (it starts the GUI); `crates/gezik-vfs/tests/timing.rs` (ignored, run by hand in release) times opening 10,000- and 100,000-entry zips instead. Idle memory and start time were not measured here (no GUI runs).

## Follow-ups

- 16b: writing (Put/Delete/Rename/MakeDir), "Update in Archive", the lock badge, thumbnails for `RANDOM_READ` archives, Extract to Preview.
- Crumbs inside deep archives are not collapsed into "…" (only the disk part is).
- A Copy To… into a missing folder makes it; undo leaves the folder (shortcut noted in `tasks.rs`).
- Passwords asked from the preview's thread wait for the answer; a selection change meanwhile does not close the question.
- An archive inside an archive is not read again when the outer archive changes (it was taken out once); leaving and entering it again reads it anew.
- A `\` in an entry's name is a folder separator everywhere, inside archives as when extracting (`safe_join`): a Unix tar entry with a literal backslash shows as folders on every system.
- A drag's own folder stays in the temporary area until Gezik quits.
- Copy inside an archive puts no files on the system clipboard (spec §4.6, decision 11: Gezik's own clipboard and the addresses as text), so a paste in Explorer or Finder does nothing; drag or Copy To… instead. Taking the selection out at Copy time (≤ 256 MB, as a drag) and putting real files there is a possible later step.
- Screen test: a right-click on a row inside an archive acts on that row (it is selected by `prepare_menu`, as on disk) but the row did not look selected while Gezik's own menu was open. Disk rows on Windows open Explorer's menu instead, so the difference may be Gezik's menu opening before a frame shows the selection (the trash's rows use the same menu); not changed in 16a, to look at with that menu.

## Size and checks

- Release exe 30,817,792 B against master's 30,599,168 B (81f3ba1 built here): **+218,624 B** (budget +262,144 B). Archive search and nested archives stay in 16a.
- Opening a zip (release, `tests/timing.rs`): 10,000 entries opened and the folder listed in 93 ms (target ≤ 150 ms), 100,000 in 562 ms. The 100,000-entry index stays under 8 MB (unit test).
- `cargo fmt`, `clippy --workspace --all-targets` clean; `cargo test --workspace` passes on Windows. `cargo check` of gezik-core, gezik-config and gezik-vfs for `x86_64-unknown-linux-gnu` and `aarch64-apple-darwin` passes; the app crate is not cross-checked here (it needs the targets' system libraries, fontconfig).
- `gezik-lang check`: all five catalogues complete, 0 errors (Turkish by hand, the others machine-translated and fuzzy).
- Not measured here (no GUI runs): idle memory, start time, the memory return after leaving an archive. Nothing is loaded at start (the crate's objects are made on first use) and no timer or thread runs while idle.
