# 16e: Git commands — notes

Plan `../../plans/2026-10-14-gelismis-16e.md`, spec `../../specs/2026-10-13-gelismis-design.md` §9, §14 16e. Stacked on 16d (`feat/git-16d`, 2ff2247 merged in).

## What is in

- **Actions** (`actions!`, no keys; `Action::ALL` 135 → 144): `git-stage`, `git-unstage`, `git-commit`, `git-push`, `git-pull`, `git-fetch`, `git-switch-branch`, `git-discard`, `git-compare-head`. Template lines, `docs/shortcuts.md`, palette (from `Action::ALL`), macOS menu bar **Git** menu after Go. Refused in the trash view.
- **Menus** (ids 3252–3260, branches 3300–3349): a row's `Git ▸` (only in a repository folder, not in results): Stage, Unstage, Discard Changes…, Compare with HEAD (greyed when the rows' marks say it does nothing), then Commit…, Push, Pull, Fetch, Switch Branch…. Gezik's own menus (macOS, Linux) put it into Tools ▸ under a "Git" heading when `MAX_SUBMENUS` is full. The status bar's Git part is a button: its menu has the repository's commands and the names of the files deleted under the folder shown (16d deviation 3), at most 20 and "and N more".
- **Running** (`git_commands.rs`): a queue; a command starts when no other runs in its repository or in the pane's panel (`may_start`, tested). It is made on a thread through `git.rs` `prepared` (16d's safe path, see below), then runs in the pane's command panel (`CommandLine::run_process`, no shell, nothing in the history). Push, pull, fetch, commit open the panel and stream; stage, unstage, switch open it only on failure. Stop ends git with what it started; Run Again queues the same command. A panel busy with a `>` command asks "A command is still running. Stop it?" first. When a command ends every pane in that repository runs its status again; a status due while a command runs waits for it (`busy`).
- **Commit…** (`ui/widgets/git-commit.slint`): the staged files come from `git diff --cached --name-only -z` first; a multi-line message in the mono font with a faint line at column 72, the staged list, "Stage all changes first" (`-a`), Commit (off with an empty message, or nothing staged without the box), Cancel; Ctrl+Enter / ⌘↩ commits, Esc cancels. `git commit [-a] -F -`, the message on git's input, git's own cleanup. The draft stays per repository for the run of Gezik and goes after a successful commit.
- **Switch Branch…**: `git for-each-ref --count=50 --sort=-committerdate --format=%(HEAD)%(refname:short) refs/heads/` on a thread, then a menu (the current one marked and greyed) at the status bar's Git part (or where the last row menu was); `git switch <branch>`.
- **Discard Changes…**: rows map to the status's entries (a folder to its changed files inside, a file inside an untracked folder to itself); worktree changes (`Modified`, `StagedModified`) and untracked only; staged-only, ignored, conflicts stay. Asked first; not on a drive without a trash. One engine job (`DiscardTask`, one item at a time): the file to the trash (`trash_path`), then a tracked one `git restore --worktree -- <path>` (from the index). Outcomes `Trashed` + `Created` at the same path: the engine's undo sees a replaced file and swaps the trashed one back over git's (`SwapBackTask`, 16b's archive path), so one Ctrl+Z brings all back. A restore that fails puts the file back from the trash.
- **Compare with HEAD**: `git cat-file --filters HEAD:<path>` to `%TEMP%/gezik-head-<pid>/HEAD - <name>` (emptied at each compare), then step 11's compare (built-in, or `[tools] diff`).
- **Credentials**: nothing of Gezik's: the user's helper, ssh-agent. `GIT_TERMINAL_PROMPT=0`. A failed command whose output says it wanted a password or key ("Authentication failed", "Permission denied (publickey", "could not read Username/Password", "terminal prompts disabled", "Host key verification failed") gets **Open in Terminal** in the panel: the terminal (7a) in the repository, the command on the clipboard.
- Paths go to git from the repository's root with `/`, after `--`; over 32 KB through `--pathspec-from-file=- --pathspec-file-nul` on its input (`spawn_piped_input`, new in `gezik-platform`). `GIT_LITERAL_PATHSPECS=1`: `*`, `[` in a name are no patterns. Rows are taken by the folder's real path (16d's `Repo::real`), as the root is.

## Safety (the stance)

Every git call goes through `git.rs` (`prepared`, `read`): 16d's ground (git by full path, 2.31 or newer, settings through `GIT_CONFIG_COUNT/KEY/VALUE`, `GIT_ALLOW_PROTOCOL=none`, no prompt, `GIT_DIR`… removed, `core.fsmonitor=false`). By `Trust`:

| Commands | Repository's filter drivers | Hooks | Transport |
|---|---|---|---|
| status, branch list, staged list, HEAD file; stage, unstage, switch, discard's restore (`Local`) | emptied (a `git config` look first; unreadable config refuses) | none run by these | none |
| fetch, pull (`Network`) | emptied | pull's merge hooks run, as git's | `http:https:ssh:git:file` only |
| commit (`Hooks`) | run as git runs them | run (spec §9.2) | none |
| push (`HooksNetwork`) | (none used) | `pre-push` runs | `http:https:ssh:git:file` only |

Commit and push run the repository's hooks by design (spec §9.2, as git does): a repository downloaded with a hostile `.git/hooks` runs them when you commit or push in it, as in a terminal. `ext::` and every other transport stay refused (checked: a remote `ext::sh -c touch…` fails and runs nothing). Tested with the real git: stage in a repository whose local `filter.evil.clean` writes a marker runs nothing.

## Deviations

1. **Switch Branch is a menu of its own**, not a `▸` submenu: the branches come from a git run, and the native Explorer menu cannot wait for it. The row's and status bar's item is "Switch Branch…".
2. **Compare with HEAD uses `git cat-file --filters`**, not `git show`: the same blob with git's line-end conversion (and the user's global filters such as LFS), so a CRLF work tree does not differ on every line.
3. **Commit and push do not empty the repository's filter drivers** (they run its hooks anyway; spec §9.2); the other commands do, so a repository whose LFS filter is set in its own config (`git lfs install --local`) gets raw content on Stage/Pull from Gezik (known limit below).
4. **Run Again of a commit** commits the same message again (what the panel showed).
5. **Discard on a folder** stands for its changed files (not the folder as a whole): ignored files in it never go to the trash.
6. Builds here needed `RUST_MIN_STACK=268435456` (rustc overflowed its stack on the `gezik` bin at 64 MiB twice).

## Known limits

- A repository-local filter driver (e.g. LFS installed with `--local`) is not applied by Stage, Unstage, Switch, Pull or Discard from Gezik; the terminal does. LFS installed globally (the usual) works.
- ssh may still ask for a key's passphrase on `/dev/tty` when Gezik was started from a terminal (Unix); Stop ends it. ssh-agent avoids it.
- A partial clone's missing objects are not fetched on Switch (`GIT_NO_LAZY_FETCH`).
- The HEAD copy for Compare stays in `%TEMP%` until the next compare (one folder per run).
- Quiet commands (stage, unstage, switch) replace the panel's previous output.
