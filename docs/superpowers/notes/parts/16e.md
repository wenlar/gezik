# 16e: Git commands — notes

Plan `../../plans/2026-10-14-gelismis-16e.md`, spec `../../specs/2026-10-13-gelismis-design.md` §9, §14 16e. Stacked on 16d (`feat/git-16d`, 2ff2247 merged in).

## What is in

- **Actions** (`actions!`, no keys; `Action::ALL` 135 → 144): `git-stage`, `git-unstage`, `git-commit`, `git-push`, `git-pull`, `git-fetch`, `git-switch-branch`, `git-discard`, `git-compare-head`. Template lines, `docs/shortcuts.md`, palette (from `Action::ALL`), macOS menu bar **Git** menu after Go. Refused in the trash view.
- **Menus** (ids 3252–3260, branches 3300–3349): a row's `Git ▸` (only in a repository folder, not in results): Stage, Unstage, Discard Changes…, Compare with HEAD (greyed when the rows' marks say it does nothing), then Commit…, Push, Pull, Fetch, Switch Branch…. Gezik's own menus (macOS, Linux) put it into Tools ▸ under a "Git" heading when `MAX_SUBMENUS` is full. The status bar's Git part is a button: its menu has the repository's commands and the names of the files deleted under the folder shown (16d deviation 3), at most 20 and "and N more".
- **Running** (`git_commands.rs`): a queue; a command starts when no other runs in its repository or in the pane's panel (`may_start`, tested). A repository is held (`HELD`, shared with the engine's thread) by a running command or a discard; its status waits while it is held (`busy`). The command is made on a thread through `git.rs` `prepared` (below), then runs in the pane's command panel (`CommandLine::run_process`, no shell, nothing in the history). Push, pull, fetch, commit open the panel and stream; stage, unstage, switch open it only on failure. Run Again queues the same command. A panel busy with a `>` command asks "A command is still running. Stop it?" first. When a command ends every pane in that repository runs its status again.
- **Stop**: on Unix git first gets SIGINT (its process group) and a second to end by itself, taking its lock files away; then it is killed. On Windows it is ended at once; a later command that fails on a lock file says "Git left …/index.lock behind: delete it only if no git is running" (never deleted by Gezik).
- **Commit…** (`ui/widgets/git-commit.slint`): the staged files (`git diff --cached --name-only`) and, for "Stage all changes first" (`-a`), the tracked files changed in the work tree too (`git diff --name-only`): the list shows what the commit takes, and changes with the box. A multi-line message in the mono font with a faint line at column 72 (the dialog is wide enough for 72 columns, within the window), Commit (off with an empty message or nothing to commit), Cancel; Ctrl+Enter / ⌘↩ commits, Esc cancels. `git commit [-a] -F -`, the message on git's input, git's own cleanup. The draft stays per repository for the run of Gezik and goes after a successful commit. While the dialog is open the window's shortcuts stay out of it (`handle_key`; a test checks every layer over the window).
- **Switch Branch…**: `git for-each-ref --count=50 --sort=-committerdate --format=%(HEAD)%(refname:lstrip=2) refs/heads/` on a thread, then a menu (the current one marked and greyed) at the status bar's Git part (or where the last row menu was); `git switch --end-of-options <branch>` (a branch named `-x` is no option).
- **Unstage** before the first commit (no HEAD): `git rm --cached -r -q -- <paths>`.
- **Discard Changes…**: rows map to the status's entries (a folder to its changed files inside, a file inside an untracked folder to itself); worktree changes (`Modified`, `StagedModified`) and untracked only; staged-only, ignored, conflicts and submodules stay. Asked first; not on a drive without a trash. One engine job (`DiscardTask`, one item at a time) that holds the repository (it waits for a running command). Each item's status is read again first (`git status -- <path>`): one that changed since the list was shown is skipped with a note. A file goes to the trash (`trash_path`), then a tracked one gets `git restore --worktree -- <path>` (from the index). An untracked folder gives only its untracked, not ignored files (`git ls-files -o --exclude-standard`; a repository inside it is listed as `dir/` and left alone). Outcomes `Trashed` + `Created` at the same path: the engine's undo sees a replaced file and swaps the trashed one back over git's (`SwapBackTask`, 16b's archive path), so one Ctrl+Z brings all back. A restore that fails puts the file back from the trash; if that fails too the error names where it is in the trash.
- **Undo leaves git's version in the trash**: the swap-back moves the file git wrote to the trash before the original takes its place (so a redo can swap again). After Discard + Ctrl+Z the bin therefore holds one entry per tracked file: the committed version, which git still has. Intended.
- **Compare with HEAD**: `git cat-file --filters HEAD:<path>` (every program setting of the repository blanked, below) to `%TEMP%/gezik-head-<pid>/HEAD - <name>` (emptied at each compare), then step 11's compare (built-in, or `[tools] diff`).
- **Credentials**: nothing of Gezik's: the user's helper, ssh-agent. `GIT_TERMINAL_PROMPT=0`; for push, pull and fetch `GIT_SSH_COMMAND=ssh -o BatchMode=yes` unless `GIT_SSH`, `GIT_SSH_COMMAND` or the user's own `core.sshCommand` is set. A failed push, pull or fetch whose output says it wanted a password or key gets **Open in Terminal**: the terminal (7a) in the repository, a fixed `git push` / `git pull` / `git fetch` on the clipboard.
- **Subfolder changes**: the folder watcher sees the folder shown, the `.git` watch HEAD, index and refs; a file changed elsewhere in a sub-folder (not staged: the index does not change) shows once Gezik's window comes back to the front (every pane in a repository runs its status again then) or with F5. No folder tree is watched (Linux would need an inotify watch per folder) and nothing polls.
- Paths go to git from the repository's root with `/`, after `--`; over 32 KB through `--pathspec-from-file=- --pathspec-file-nul` on its input (`spawn_piped_input`, new in `gezik-platform`). `GIT_LITERAL_PATHSPECS=1`: `*`, `[` in a name are no patterns. Rows are taken by the folder's real path (16d's `Repo::real`), as the root is; git's paths become system paths before the trash sees them.

## Safety (the stance)

Every git call goes through `git.rs` (`prepared`, `read`): 16d's ground (git by full path, 2.31 or newer, settings through `GIT_CONFIG_COUNT/KEY/VALUE`, `GIT_ALLOW_PROTOCOL=none`, no prompt, `GIT_DIR`… removed, `core.fsmonitor=false`).

**Program settings of the repository**, for every command: a `git config -z --show-scope --get-regexp` look first (an unreadable config refuses the command) for `filter.*.clean/process/smudge`, `merge.*.driver`, `core.sshCommand/gitProxy/askPass`, `credential.*helper`, `remote.*.uploadpack/receivepack/proxy`, `diff.*.command/textconv`. Each one set at `local` or `worktree` scope (or in a file included there) is replaced: by the user's own value for that key (system, global, command line) when there is one, else by nothing, git's own merge (`git merge-file`) for a merge driver, git's own upload-pack/receive-pack for a remote. Credential helpers are a list: it is reset and the user's helpers come back in order. A remote's upload-pack and receive-pack cannot be set twice (git keeps the repository's), so fetch, pull and push get `--upload-pack=` / `--receive-pack=` instead. The user's global settings (LFS, a credential manager) keep working.

| Commands | Hooks | Transport |
|---|---|---|
| status, branch list, staged lists, HEAD file; stage, unstage, switch, discard (`Local`) | none: `core.hooksPath` is an empty folder of Gezik's | none |
| fetch, pull (`Network`) | none (pull's post-merge, commit-msg, post-checkout neither) | `http:https:ssh:git:file` only |
| commit (`Hooks`) | the repository's (spec §9.2) | none |
| push (`HooksNetwork`) | the repository's (`pre-push`, `reference-transaction`) | `http:https:ssh:git:file` only |

Commit and push run the repository's hooks by design (spec §9.2, as git does): a repository downloaded with a hostile `.git/hooks` runs them when you commit or push in it, as in a terminal; its config's programs still never run. Pull makes merge commits but runs no hook: the spec names hooks only for commit (§9.2); a terminal pull does run them. `ext::` and every other transport stay refused.

Tested with the real git, each against a control run of plain git that shows the hostile setting does run: smudge filter and post-checkout hook (through the repository's `core.hooksPath`) on Switch and on the HEAD read; `remote.origin.uploadpack` and `core.sshCommand` on Fetch; merge driver and post-merge hook on Pull; clean filter on Stage; `ext::` remote.

## Deviations

1. **Switch Branch is a menu of its own**, not a `▸` submenu: the branches come from a git run, and the native Explorer menu cannot wait for it. The row's and status bar's item is "Switch Branch…".
2. **Compare with HEAD uses `git cat-file --filters`**, not `git show`: the same blob with git's line-end conversion (and the user's global filters such as LFS), so a CRLF work tree does not differ on every line.
3. **Pull runs no hooks** (only commit and push do).
4. **Run Again of a commit** commits the same message again (what the panel showed).
5. **Discard on a folder** stands for its changed files (not the folder as a whole): ignored files and nested repositories never go to the trash; empty folders stay.
6. **Subfolder changes show when the window comes back** (or F5), not at once: no recursive watch.
7. Builds here needed `RUST_MIN_STACK=268435456` (rustc overflowed its stack on the `gezik` bin at 64 MiB twice).

## Known limits

- A repository-local filter driver (e.g. LFS installed with `--local`) is not applied by any Gezik command; the terminal does. LFS installed globally (the usual) works.
- A merge in a repository with its own merge driver uses git's three-way text merge instead.
- A partial clone's missing objects are not fetched on Switch (`GIT_NO_LAZY_FETCH`).
- The HEAD copy for Compare stays in `%TEMP%` until the next compare (one folder per run); the empty hooks folder stays there too.
- Quiet commands (stage, unstage, switch) replace the panel's previous output.
- Windows: Stop kills git at once; a lock file it leaves is named in the next failure's note.
