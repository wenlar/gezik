# 14d: settings export and import — notes

Plan `../../plans/2026-10-12-tasinabilirlik-14d.md`, spec §7.

## Follow-ups

- **No save or open dialog:** Gezik has no file dialog; Export and Import take a path in a text field (Enter). The export's default is `Documents/gezik-settings-<date>.zip`; an existing file is refused instead of asked about.
- **Boxes per kind of file, not per file:** the import preview has one box for settings.toml, the themes, the templates and the folder views, each listing its files (new, replaces; "N the same here").
- **"3 paths do not exist here" is not listed:** a zip from another OS only says that paths written without a `{token}` may not exist on this computer.
- **Templates over 256 MB** are refused with "leave them out" instead of asked about.
- **Restore Backup does not remove files:** it replaces the files in the backup (after its own backup); a theme added since stays. Undo Import does remove what the import added.
- **Folder views:** `views.toml` is written by the import and the folder views in memory are replaced at once (pending view changes are flushed first). `views.toml` stays in the config folder (14e's split makes it local).
- **The red row** is a row with a red title (`kind 7`) plus a red status line, not a red section header.
- **No menu items:** the page's rows and the palette (`export-settings`, `import-settings`) are the way in; the 2870–2889 menu ids are unused.
- **An undo is itself backed up** first, so Restore Backup can go back to the imported state.
- **Windows GUI test** not run (no GUI while the user is at the PC).
