# 16c: commands in the address bar — notes

Plan `../../plans/2026-10-14-gelismis-16c.md`, spec `../../specs/2026-10-13-gelismis-design.md` §7, §14 16c.

## What is in

- **`>` mode** (`gezik/src/command_line.rs`): an address that starts with `>` (spaces before it passed over) is a command. It runs only from the address field's Enter (`on_navigate`, the one path `TextField.accepted` takes); a paste, a suggestion clicked or chosen with ↑/↓ + Enter (it is written into the field), a session or a tab set never run one. The suggestion list shows the command history (rows whose "path" starts with `>`, which no folder's does). `run-command` (palette, no key) opens the address bar with `>`; `toggle-command-output` shows or hides the panel (`Action::ALL` 135).
- **Where**: `Location::folder()`; none (This PC, the trash, inside an archive) gives "Commands run in a folder on disk". On Windows cmd is not started in a `\\server\share` folder (it would run in the Windows folder): the panel says to use PowerShell.
- **Shell** (`[command-line] shell`, `shell-args`): Windows `%ComSpec% /v:on /d /s /c "chcp 65001>nul & "%ComSpec%" /d /s /c !GEZIK_COMMAND!"` through `raw_arg`, `GEZIK_COMMAND` holding `"<text>"`: the outer cmd sets the console to UTF-8 and puts the text in only by delayed expansion (after it parsed its own line), the inner one starts with UTF-8 as its code page, takes off the outer quotes and runs the rest as typed; `powershell`/`pwsh` `-NoLogo -NoProfile -NonInteractive -Command <fixed script>`, the script setting UTF-8 output and progress off, then running the command it decodes from `GEZIK_COMMAND` (base64 UTF-8); Unix `$SHELL -c <text>` (else `/bin/sh`); a full path gets `shell-args` and the text. Environment: `GEZIK_FILE`, `GEZIK_FILES`, `GEZIK_DIR` (for cmd each path in double quotes and `GEZIK_FILES` as `"a" "b"`; elsewhere bare, `GEZIK_FILES` one per line; a list too long for one variable goes to a private temporary file `GEZIK_FILES_LIST` names), `TERM=dumb`, `NO_COLOR=1`, `CLICOLOR=0`, `PAGER=cat`, `GIT_PAGER=cat`, `GIT_TERMINAL_PROMPT=0`. Never elevated (it runs as Gezik does).
- **Process** (`gezik-platform` `ChildProcess::spawn_piped`, `try_wait`): no window, its job object (Windows) or process group (Unix), input from the null device (EOF at once), output and error output as raw pipes, each read by a thread of its own while it runs. Lines: split at `\n`, the part after the last `\r` kept (progress rewritten in place), UTF-8 else the OEM code page (`gezik_platform::decode_oem`, `GetOEMCP`), escape sequences and control characters out (`gezik-core/src/ansi.rs`), at most 16 KB a line.
- **Panel** (`ui/widgets/command-output.slint`, one per pane under its list): the command, its folder, "Running… 3 s" then "Exit code 0 · 0.4 s" (green for 0, red otherwise), "Stopped", "Ended by a signal"; Stop / Run Again, Copy Output, Close; error output in the warning color; the list follows the end unless scrolled up; the top edge drags its height (80–600 px). At most 2 MB kept: past it the oldest lines go down to 1.5 MB in one go and "Earlier output dropped" shows. A 33 ms timer takes new lines only while a command runs. Once the shell ended (and its output closed, or 0.5 s went by) the folder is read again once if the pane still shows it.
- **Another command while one runs**: "A command is still running. Stop it?" (Stop and Run / Cancel). Close stops a running command; Esc on the list closes a panel whose command ended; the pane closing (or its window) ends it.
- **History** (`state.toml` `[command-line] history`, newest first, no twins, 100): a command typed with a space after `>` is not kept; `[history] remember = false` keeps none and forgets them; `clear-history` forgets them with the folders.

## Deviations

1. **History rows are chosen, not run**: ↑/↓ move in the list (↓ opens it), Enter or a click on a row writes it into the field; a second Enter runs it. The spec's "↑/↓ go through the history" is kept this way so that choosing never runs.
2. **Close also stops** a running command; Esc closes only a panel whose command ended; `toggle-command-output` only hides (the command goes on).
3. **No menu ids** (3350–3379 stay free): the panel's buttons are Slint buttons, the actions are in the palette.
4. **What the shell leaves running** once it ended by itself (`start winword`, `code .`, `gimp &`) goes on, on both systems: the job is let go (kill-on-close off) on Windows, the process group is never signalled on Unix. A running command (the shell still there) ends with Stop, Close, the pane or Gezik quitting.
5. **cmd in a network folder is refused** (not in the spec): cmd would quietly run in the Windows folder.
6. **The panel's height** is not remembered: it is 180 px each time it opens.

## After the code review (PR #143)

- **cmd and the selection**: cmd puts `%VAR%` in before it reads the line, so a name with `&`, `|`, `^`, `(`, `<`, `>` could start a command; every path cmd gets is in double quotes (no Windows name holds `"`), and `GEZIK_FILES` is `"a" "b"` (a newline cut cmd's line at the first path). Test: a file named `a&echo INJECTED&rem .txt` echoes as one name.
- **Large selections**: past 7,000 characters (cmd), 30,000 (other Windows shells) or 100 KB (Unix; Linux allows 128 KiB per string) `GEZIK_FILES` is left out and `GEZIK_FILES_LIST` names a file (0600 on Unix) with one path per line, removed when the run ends; the panel says so.
- **Floods**: the cap counts 64 bytes per line besides its text; the readers hold at most 2 MB not yet shown (the oldest dropped, the pipes never stall); a tick shows at most 2,000 lines; the panel's rows are the output itself (`OutputModel`), lines dropped from the start are one removal, never a rebuild.
- **After the run**: the readers of a pipe a background program still holds read and drop (`orphaned`).
- **Background programs live on** (deviation 4): `ChildProcess::let_go` takes kill-on-close off the job once the shell ended by itself.
- **A held Enter** in the address field is swallowed (`held_enter`): it neither runs a command again nor runs one just written from the history. The "still running" question has Cancel first (Enter and Esc both keep the command).
- **PowerShell errors** came as CLIXML with `-EncodedCommand` and a piped error output (`-OutputFormat Text` does not help): the command now goes through `-Command` and an environment variable. Test: `Get-Item nope` gives a plain error line.
- **Stop during the half second after the shell ended** keeps its exit code (no "Stopped").
- **Long lines** are cut after a byte below `@` in their last kilobyte (a whole character in UTF-8 and in every OEM code page), else before a UTF-8 character.
- **Quitting** ends running commands (`end_all`): Unix process groups would outlive Gezik.
- **After the screen test (t16c)**:
  - cmd's own output (`echo`, `dir`) lost ğ, ş, ı (OEM 437 has none; cmd reads the code page only when it starts, so `chcp` in the same line did not help): cmd now runs in two, the inner one started after `chcp 65001` (above). Console programs (ping, where) write UTF-8 too. Test: `echo ğüşıİ`, `dir /b` of a folder with them and `where` of such a file, plus `^`, `%`, `!`, `"x&y"` giving the same text as before.
  - The panel did not follow new lines: it follows the end (once the list has grown) while it is at the end, and stays where it is once scrolled up.
- **Known window**: the shell joins its job object just after it starts (std has no suspended start to resume); a program it started in those microseconds would escape Stop. Shells start nothing that fast.

## Known limits

- No TTY: interactive and full-screen programs end or fail at once; colors are not shown. Long lines are clipped in the panel (Copy Output has them whole).
- Output without a line end shows when the line ends or the program does (a prompt like `set /p` shows at the end).
- Old Windows programs that write in the ANSI rather than the OEM code page show wrong letters.
