# 16g: phones over MTP on macOS and Linux — notes

Plan `../../plans/2026-10-14-gelismis-16g.md`, spec `../../specs/2026-10-13-gelismis-design.md` §10.3, §10.4, §13, §14 16g, §19 question 4. Built on 16f (PR #151) with its review fixes (365c660d) merged in.

## What is in

- **Finding phones without libmtp** (`gezik-platform/src/mtp/`): a phone is a USB device with an MTP interface: class 6/1/1, or class 255 named "MTP" (older Android); Apple's are left out (an iPhone shows only on Windows, spec §17). Its id is `usb:<bus>:<address>`, the numbers libmtp's raw device list carries. macOS (`watch_mac.rs`) reads the IORegistry (`IOUSBHostInterface`, the name from `USB Product Name`, the bus from `locationID >> 24`, `USB Address`); Linux (`watch_linux.rs`) reads `/sys/bus/usb/devices` (`bInterfaceClass`…, `interface`, `busnum`, `devnum`, `product`/`manufacturer`, `serial`).
- **Events**: macOS: an IOKit notification port on the main run loop (`kCFRunLoopCommonModes`), first-match and terminated notifications for `IOUSBHostInterface`; no thread. Linux: one thread (`gezik-phones`, 64 KiB stack) sleeping in `recv` on a `NETLINK_KOBJECT_UEVENT` socket (kernel group 1); an `add` of a `usb_interface` with `INTERFACE=6/…` or `255/…`, a `remove` of a `usb_device`, or lost events (`ENOBUFS`) re-read the list. Both start after the first frame and only while `[devices] phones` is on; the call is carried to the UI thread with `slint::invoke_from_event_loop` (`phones.rs`).
- **libmtp** (`libmtp.rs`), loaded with `libc::dlopen` (as `audio/linux.rs` loads PulseAudio) the first time a phone is opened, never linked: the path in `[devices] libmtp`, then macOS `/opt/homebrew/lib/libmtp.9.dylib`, `/usr/local/lib/libmtp.9.dylib`, Gezik's download; Linux `libmtp.so.9`. A library that loads but lacks a function is passed over (the error names the function); none at all is `NoLibmtp`. Not loaded is tried again on the next open (installing libmtp needs no restart). Fifteen functions: `Init`, `Detect_Raw_Devices`, `Open_Raw_Device_Uncached`, `Release_Device`, `Get_Storage`, `Get_Files_And_Folders`, `Get_Filemetadata`, `destroy_file_t`, `Get_File_To_Handler`, `Send_File_From_Handler`, `Create_Folder`, `Delete_Object`, `Set_File_Name`, `Get_Errorstack`, `Clear_Errorstack`.
- **The session** implements 16f's `Session`. Object ids are `<storage>:<object>` (a storage `…:4294967295`, libmtp's root). Calls go one at a time under a mutex; errors are libmtp's error stack text. `storages` (none for a locked phone: `Get_Storage` returns -1 then), `list` (folders by file type 0), `read_to` through the put handler (stop: `CANCEL`, `Interrupted`; the bytes are counted and a file shorter than its size is `UnexpectedEof`), `put` through the get handler with Gezik's own `LIBMTP_file_t` (filename buffer Gezik owns; a source that ends before the size given fails; an object made before the data failed is deleted), `mkdir`, `delete` (a storage is refused; a folder the phone will not delete with things in it is emptied first, a file never), `rename` (a storage is refused; `Set_File_Name` on libmtp's own record, folders too), `writable` (any storage with access capability 0), `connected` (the id still found in the IORegistry or `/sys`). `MtpVfs` (16f) does the rest: undo by ids, lost device, one failed put not ending the job.
- **Opening failures**: Linux without access to `/dev/bus/usb/BBB/DDD`: "No permission to open the phone (libmtp's udev rules)"; listed but not opened: macOS "Another app is using the phone (Image Capture, Android File Transfer). Quit it and try again." (`ptpcamerad` included), Linux "Another app is using the phone. Quit it and try again."; Linux without libmtp: "Install libmtp (e.g. sudo apt install libmtp9)" in the status bar.
- **macOS download box**: `Need::Phones` → `Tool::Libmtp`, title "libmtp needed": "Phones need libmtp (~…, free)." with Download / Where does it come from? / Cancel; with no build: "…cannot download it for this system yet: install it yourself (brew install libmtp)."; downloads off: "…or set libmtp under [devices] in settings.toml.". After the download the phone opens by itself.
- **gvfs** (Linux): before opening, `mtp::gvfs_mount(id)` looks in `/run/user/<uid>/gvfs` for `mtp:host=<udev ID_SERIAL>` ending in the phone's serial, or the older `mtp:host=[usb:BBB,DDD]` (percent-decoded); found, the tab goes there as a plain path (redirect), so every file operation is the ordinary one and gvfs keeps the device.
- **Tool::Libmtp** in `MANIFEST`: macOS arm64 and x64, one universal `libmtp-1.1.23-macos-universal.tar.xz` (`libmtp.9.dylib`, `libusb-1.0.0.dylib`, `COPYING`, `SOURCE.txt`), **pending** (`sha256: PENDING`, `size: 0`): `build_for` leaves pending entries out, so no download is offered until the maintainer publishes. `scripts/tools/prepare-libmtp.sh` builds it on a Mac from the pinned sources (`sources.sha256`: libusb 1.0.30, libmtp 1.1.23, both released over two weeks ago, hashes taken here from the GitHub release files); `scripts/tools/README.md` "libmtp (macOS)" has the steps; `THIRD-PARTY.md` the LGPL note.
- **Settings**: `[devices] libmtp = ""` (template, schema, `docs/configuration.md`; a relative path is a warning and ignored).

## Deviations

1. **No `Look for Phones` menu item** (spec §10.3, §10.5): class 255 interfaces named "MTP" are recognised without libmtp, so the old phones it was for show by themselves; no menu id used.
2. **No version string check** (spec: `LIBMTP_VERSION_STRING` ≥ 1.1.17): that is a compile-time macro, libmtp has no run-time version; every function used is looked up instead, and a missing one is named in the error.
3. **`Set_File_Name` for folders too** (spec lists `Set_Folder_Name`): libmtp maps the folder type to an association and does the same; one function fewer.
4. **No thumbnails** (`Get_Thumbnail` not bound), as on Windows in 16f.
5. **Phones are not `Drive` rows** (16f's deviation 1 stands).
6. **The download is pending**: the `MANIFEST` entries exist but are disabled (no real hashes yet); until then macOS needs Homebrew's libmtp.
7. **The event re-reads more than phones**: macOS hears every USB interface come and go, Linux every class 6/255 interface added and every USB device removed; each costs one IORegistry or `/sys` read on a worker (no libmtp).
8. **Linux's "another app" message names no app** (a file manager, KDE's kiod, another libmtp program all look alike).

## Known limits

- Turning `[devices] phones` off at run time leaves the Linux thread asleep (it starts once and stops with Gezik); no phones are read while off.
- A phone unplugged and plugged in again gets a new id (its address changes): an open session is lost, as 16f handles it; a tab (or a restored session) on the old id goes to the phone of that name now.
- libmtp writes debugging text to stderr on some errors; its error texts are English (the device's own output, spec §11.4).
- A phone gvfs holds is a plain folder: Gezik's phone notes ("Unlock the phone…", read-only) do not show there; gvfs's own errors do.
- libmtp's dates are what it makes of the device's string (`time_t`).
- `ptpcamerad` on macOS can take the phone again after Image Capture quits; `killall ptpcamerad` frees it (checklist 412).
