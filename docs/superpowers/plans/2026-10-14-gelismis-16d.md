# Gelişmiş 16d (Git durumu) — Uygulama Planı

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Bir depo klasörü gösterilirken sistem `git`'iyle tek bir `git status --porcelain=v2 -z --branch` koşusu (gösterilen klasöre sınırlı, iptal edilebilir, zaman aşımlı); satırlarda işaretler (çakışma, değişti, hazırlandı, hazırlandı + değişti, eklendi, yeniden adlandırıldı, izlenmiyor, yok sayıldı soluk), klasörde toplanmış işaret, Git sütunu (sıralanır), `git:` süzgeç kelimeleri, `GroupBy::Git`, durum çubuğunda dal ve önde/geride. Depo dışında süreç yok; depo bulma yükleme iş parçacığında `.git` bakışı; ağ sürücüsünde kapalı; arşivde kapalı. Yenileme klasör izleyicisi ve `.git` izleyicisiyle, 300 ms birleştirme; zamanlayıcı ya da yoklama yok. Boşta 0, exe ≤ +262.144 B.

**Spec:** `docs/superpowers/specs/2026-10-13-gelismis-design.md` §8, §11.1, §13, §14 16d; §18 karar 12, 13, 23; §19 soru 2. Plan önceden onaylıdır. Dal `feat/git-16d` (`master` 5c623e9), `D:\Work\gezik-16d`.

## Bulgular (kaynakta)

1. Klasör `navigation.rs` `list()` içinde yükleme iş parçacığında okunur; `LoadResult::Files` sonucu `finish_load`'da gösterilir. Depo bakışı buraya girer, sonuç `finish_load`'dan görünüme verilir.
2. `folder_tags.rs` deseni (görünüm başına koşu, `Drop`'ta iptal, `upgrade_in_event_loop` ile dönüş, kimlikle bayat sonucu atma) Git için de uygun.
3. 16c'nin `ChildProcess::spawn_piped` + `wait_or_stop` + `kill_tree`'si koşu ve iptal için yeterli.
4. `git status` gerçekten `core.fsmonitor`'u ve `filter.<ad>.clean`'i çalıştırıyor (bu makinede denendi); `-c core.fsmonitor=false` ve boş `filter.<ad>.clean=`/`process=` ikisini de durduruyor.

## Kararlar (soru sorulmadı)

1. **Güvenlik:** her koşu `-c core.fsmonitor=false -c core.quotepath=off -c protocol.allow=never`, `GIT_NO_LAZY_FETCH=1`, `--ignore-submodules=dirty` (alt modülde ikinci git süreci ve onun ayarı yok), `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE` ortamdan çıkarılır. Deponun kendi ayarındaki (`--show-scope` local/worktree) süzgeç sürücüleri önce bir `git config` koşusuyla bulunur ve `clean`/`process` boş verilir (kullanıcının genel ayarındaki git-lfs'e dokunulmaz). git tam yoluyla başlatılır (PATH'te kendimiz ararız; Windows'ta klasördeki `git.exe` asla).
2. **`.git` izleme:** gitdir özyinelemesiz + `refs/` özyinelemeli (dal ve uzak dal değişimi; spec "özyinelemesiz" diyor, `refs/heads/main` iki kat aşağıda). `*.lock`, `objects/`, `logs/` olayları sayılmaz.
3. Bölmeler arasında sonuç paylaşımı yok (her bölme kendi klasörüne sınırlı koşar; iki bölme aynı klasörü nadiren gösterir).
4. Durum çubuğundaki Git metni ayrı bir alan; tıklama (16e'nin menüsü) ve silinenlerin listesi 16e'ye.
5. Sıralama yalnız sütun başlığından (Sort by menüsüne öğe eklenmez); `[view] sort = "git"` ve `views.toml` okunur.
6. Yok sayılan satırlar kesilmiş satır gibi soluk (`cut` çizimi).
